كل فترة هنعمل ريفيو لكتاب مشهور في المجال. تابعونا على هاشتاج #ريفيو_برينتيج
البداية بكتاب Clean Code ل Uncle Bob. اللي هتلاقيه في المراكز الأولى ضمن أهم كتب لازم أي مبرمج يقراها.
▪️ الكتاب متقسم ل 17 فصل. في الفصل الأول، بيتكلم عن ال Bad Code وأضراره، وعن تعريف ال Clean Code. المقدمة دي مهمة لإنها الأساس اللي مبني عليه بقية الكتاب. الوعي بأهمية ال Clean Code هي الخطوة اللي هتخليك تقرا الكتاب ده وتكمل قرايته.
▪️الفصل التاني بعنوان Meaningful Names بيتكلم عن أهمية اختيار أسماء معبرة في الكود بتاعك، ده بيشمل (variables, classes, methods, files, etc). كل منتج طالع منك كديفلوبر لازم يكون له إسم معبر. وفي الفصل ده هيقولك إيه الأخطاء الي الناس بتقع فيها في التسمية وإيه الصح بتاعها.
▪️الفصل التالت عن ال Functions أو ال methods أو routines. أهمية إنها تكون صغيرة في الحجم، وتؤدي وظيفة واحدة، وعن عدد ال parameters اللي بيدخل لها، وتفاصيل تانية تساعدك تكتب Clean Function.
▪️الفصل الرابع عن ال Comments. إمتى تكتبه؟ وإمتى متكتبوش؟ ولو كتبته تكتبه ازاي؟ وإيه أنواع ال Comments اللي بتزود او تقلل من ال Code Cleanness.
▪️الفصل الخامس Formatting. طريقة تنسيق الكود عامل مهم، وده بيشمل ترتيب السطور واستخدام المسافات والأقواس وال indentation بطريقة تخلي الكود مفهوم.
▪️الفصل السادس عن Objects & Data Structures. بيشرح امتى تستخدم كل واحد فيهم على حساب التاني.
▪️الفصل السابع مهم جدا وبيتكلم عن ال Error Handling. من أهم قواعد ال Clean Code كيفية تعامل الكود بتاعك مع الأخطاء وال Exceptions لما تحصل. ده هيساعدك في ال debugging وفي إصلاح الأخطاء. والفصل ده بيشرح الطريقة المثالية للتعامل مع ال errors.
▪️الفصل الثامن Boundaries عن اهمية الحفاظ على الكود بتاعنا نضيف في حالة إننا احتجنا نستخدم 3rd party software أو ن integrate مع كود تاني (سواء موجود بالفعل، أو لسه هيتكتب).
▪️في الفصل التاسع بيتكلم عن ال Unit Test وال TDD وازاي نكتب Clean Unit Tests.
▪️الفصل العاشر بعنوان Classes. عن طريقة كتابتها وتطبيق مباديء ال encapsulation وال Cohesion وال Single Responsibility Principle. وفي نفس الوقت تصميمها بحيث تكون قابلة للتطور في المستقبل.
▪️هنطلع مستوى أعلى في الفصل 11 بعنوان Systems لما نتكلم عن كيفية بناء Clean System مع مقدمة قصيرة عن ال Dependency Injection واستخدام Domain-Specific Language.
▪️الفصل 12 إسمه Emergence بيناقش 4 قواعد وضعهم Kent Beck لل Simple Design. وهما باختصار (Run All Tests - No Duplication - Be Expressive - Minimal Classes and Methods).
▪️في الفصل ال 13 بيناقش ال Clean Code بالنسبة لل Concurrency. وده موضوع شائك لإن ال Concurrency من أكتر الأماكن اللي بتسبب مشاكل لو متكتبتش بصورة نضيفة ومنظمة.
▪️بداية من الفصل 14 ل 16 بيعرض Case Study لبرامج مكتوبة بطريقة مش كويسة وهيبدأ يعمل لها Refactoring بتطبيق المباديء اللي اتقالت قبل كده.
▪️الفصل 17 بعنوان Smells and Heuristics. بيعرض قايمة بال Code Smells اللي قالها Martin Fowler في كتابه العظيم Refactoring وبيضيف عليها من عنده كتير. الفصل ده ممكن تطلع منه ب Check-List مبدأية تتدرب عليها في رحلتك لل Clean Code.
☑️كتب مقترحة بعد الكتاب ده:
1️⃣ لو هتطلع لمستوى أعلى شوية ده الوقت المناسب لكتاب Clean Architecture
2️⃣ عندك كود قائم بالفعل ومحتاج تخليه Clean عليك وعلى Refactoring by Martin Fowler.
3️⃣ الكود اللي عندك قديم ومحتاج Refactoring حذر، نرشحلك كتاب Working Effectively with Legacy Code
